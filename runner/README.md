# Owner runner and telemetry

Use PowerShell from the repository root. Prepare dependencies before timed work with `./runner/prepare.ps1`; no package downloads should be needed during a run. See spec/TRUST_MODEL.md for the cooperative workspace trust model. Docker is not required and no sandbox is introduced.

- `./runner/create-run.ps1 bb-001 -TimeCeilingMinutes 180`: exact public allowlist into a sibling BenchBoard-Runs\bb-001 folder with prepared ordinary dependencies; private manifest remains in artifacts/runs. The declared execution ceiling is required at seed time, stored as canonical `timeCeilingMinutes` with derived `timeCeilingSeconds`, and is a safety bound rather than an expected duration. 180 is the intended local-Flash calibration value, not a BenchBoard constant.
- `./runner/reset.ps1 bb-001`: validate registered path, containment and links; remove previous outputs and reconstruct identical starter bytes. Active runs cannot reset.
- `node runner/supervise.mjs bb-001 EXECUTABLE ARGS...`: launch the whole cooperative task command directly in the assigned public workspace, without shell string concatenation. Use an unused run ID with fresh matching hashes. Supply `armedEvidencePath` (and `expectedTeamId`) so dispatch is gated on a live watchdog bound to this run's seeded declaration; the gate fails closed if ARMED evidence is absent, binds a different run/team/PID/ceiling/deadline, or its watchdog process is no longer alive. The ceiling comes from the seeded manifest, never from this command; a disagreeing launch-time value is rejected and evidence is rejected if the manifest ceiling changed after the official clock started. Zero exit signals completion; early launch/nonzero failure is not a valid completed outcome.
- `node runner/arm-dsh-watchdog.mjs ...`: arm the independent DSH Agent Teams deadline watchdog before dispatching external work. Supply the exact run, team and Captain IDs; loopback DSH URL; either a duration ceiling or epoch-millisecond deadline; write-once owner evidence paths; and the active DSH launch log used by the existing host authentication flow. The arming command does not return success until durable `ARMED` evidence exists. If arming or authentication fails, do not dispatch. The detached watchdog halts only the named team through the authenticated Agent Teams route, confirms durable and runtime quiescence, and never terminates DSH.
- At the declared deadline two independent mechanisms apply. For a host process tree, `supervise.mjs` requests native Windows taskkill /T /F (or a POSIX process-group kill). For DSH-managed Agent Teams, the armed watchdog issues the authenticated team-scoped halt, because a launcher exit never proves external DSH activity stopped. Both record `configuredTimeCeilingMinutes`, `startedAt`, `deadlineAt`, `terminationRequestedAt`, `observedStoppedAt`, `officialWallSeconds`, `actualWallSeconds`, `overrunSeconds`, `terminationOutcome` and a `runStatus` of COMPLETED / TIME_LIMIT / TIME_LIMIT_OVERRUN / STOP_FAILURE / INFRASTRUCTURE_FAILURE, plus the termination request and logs. Failed or unobserved termination is STOP_FAILURE with validOutcome=false and is never scoreable as a completed run; an overrun is recorded truthfully rather than rounded to the nominal deadline. Real DSH stop behavior is now exercised by the watchdog's own live validation; no DSH product change is required or authorized here.
- `node runner/evaluate.mjs bb-001`: owner-only, after ALL participant capabilities stop. Preserve submitted source; stage product in private artifacts/evaluations, replace tooling/visible tests with canonical public copies, run typecheck/build/visible/hidden/useful-test scoring. Hidden controller remains outside product files and participant workspace. No private files are served by the product. Cooperative submitted code executes locally, with no adversarial OS containment claim. Owner must verify externally managed DSH workers have stopped before evaluating/resetting.
- `node runner/collect-metrics.mjs external.json artifacts/metrics.json`: validate normalized external DSH telemetry, retain raw input and digest. No live integration or inferred usage.
- `node runner/readiness.mjs`: single READY_FOR_CALIBRATION YES/NO, requiring current hash-bound acceptance validation, owner reference UI sanity PASS for current reference bytes and independent fairness PASS / BENCHBOARD_MAY_CALIBRATE:true, with no unresolved Critical/High/Medium findings. Owner records are artifacts/acceptance-validation.json, reference-ui-sanity.json and fairness-review.json.
- `node runner/review-packet.mjs`: assemble and mechanically verify a fresh owner-only packet. Fails if any input is missing or changed, duplicated by content, stale, or a participant run output. Never copy packet into participants' workspaces. No reviewer invocation occurs.
- `node runner/freeze.mjs approval.json`: future owner-only freeze after reference sanity PASS, independent fairness and empirical duration/discrimination acceptance; current hash evidence required. Never invoked during preparation.

Tokens: input includes cache reads; total=input+output, never add cache twice. Captain aggregates exclude usage already attributed to attempts. Null means unavailable. Busy/blocked/idle intervals are exclusive and half-open; uncovered availability is unexplained idle. GPU-hours include local reserved idle time, reject overlap on one GPU, and remain separate from cloud tokens/cost. Task-normalized rates depend on decomposition and are descriptive. Retain per-attempt reliability/context/TTFT/decode/interventions and raw provenance.

Reset/evaluation need trusted owner exclusive access. Public exports reject symlinks and include no owner history or prior evidence. Private evidence and review packets remain in the owner repository. No empirical runs or DSH changes are authorized by these commands' documentation.

Candidate.4 schema 1.1 requires explicit deadlineAt, observationEndedAt and stopResult; completedAt is the actual confirmed end or null for failed/unknown stopping. Actual wall time and overrun are retained. GPU reservations require location local/cloud (optional deviceClass); legacy 1.0 reservations retain their historical local meaning. Cloud hours without provider reservation evidence remain null. Full quality/GPU-hour is available only for fully local execution; hybrid work reports local completed-task/local-GPU-hour separately, cloud token/cost/hour evidence alongside. Fresh tokens = input minus cache reads plus output; both total and fresh-token efficiencies are reported.

`npm run self-test` checks reviewed input hashes before/after and uses temporary evidence. `node runner/deadline-evidence.mjs NEW_OUTPUT` deliberately records write-once short-deadline evidence. Packet `verify PATH integrity` is historical/self-contained; `verify PATH freshness` additionally reports CURRENT/STALE versus current source. Methodology history uses immutable per-transition files.
