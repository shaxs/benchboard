# BenchBoard product requirements — v1.0
Build a polished local project/issue manager. React, TypeScript, Vite, CSS, localStorage and Vitest are available. No backend or network access is needed. Complete the current application and correct behavior that does not meet these requirements. Choose your own architecture and working approach.

Display the 18 supplied issues in Backlog, In Progress and Done. Cards show title, priority, labels and assignee; each open control has an accessible name beginning with its issue ID and uses button or link semantics. Each card container exposes data-issue-id with its stable ID; its HTML tag, component layout and CSS classes are unrestricted. Column accessible names are Backlog, In Progress and Done. Dragging onto a card inserts before it; dropping onto column space appends. Other cards keep their relative order. Movement updates status, ordering, analytics and exactly one meaningful activity event, survives reload, and offers a keyboard alternative. Drawer status changes append the issue to its new column. Repeating an unchanged action makes no event.

Click a card to open an Issue details dialog. Edit title, description, status, priority, assignee and comma-separated labels. Controls are labelled Title, Description, Status, Priority, Assignee and Labels. Text edits commit on blur; selects commit on change. Empty titles are rejected. Labels trim whitespace, use lowercase, remove empty labels and deduplicate case-insensitively. Arbitrary nonempty labels are supported. Unassigned assignee is supported. Deletion asks for confirmation; Cancel preserves the issue, Confirm delete removes it and closes its drawer. Escape and Close close the drawer, focus stays inside the drawer while open and returns to the initiating card on close. Create issue adds a new editable issue with a stable unique ID and one creation event. Deletion does not leave an invalid open drawer. Issue data remains editable under active filters.

Header has project title, Search issues, Filter priority, Filter assignee, Filter label, Filter status, Clear filters, and completion summary. Search matches title, description, label and assignee without case sensitivity. All active filters combine with AND; search also combines with filters using AND. Clearing restores all cards. Sensible empty states distinguish no matching issues and an empty project.

Analytics show Total issues, Completed issues, Completion percentage, counts for each status, priority and assignee (including Unassigned). They reflect ALL issues, including those hidden by filters, and update immediately after creation, movement, editing or deletion. Zero issues means 0% completion. Percentage is rounded to nearest integer. Activity shows meaningful creation/edit/status/priority/assignee/label actions once per committed action, newest first by raw timestamp. Text edits commit separately by field, not per keystroke. Preserve activity on reload.

Storage contract: localStorage key benchboard. v1 value {version:1, issues:Issue[], activity:Activity[]}; supplied types and JSON fixtures describe fields. Preserve IDs, issues, order and activity when migrating supplied v0 {version:0,tasks:Issue[],activity:Activity[]} at the same key. Write v1 after migration; repeated reload is idempotent. Empty issues stay empty. Missing, invalid JSON or structurally invalid storage safely recovers to the fixture. Storage write failure must not crash the UI; show persistence feedback. Filters need not persist.

Aim for a professional project-management experience: clear information hierarchy, readable cards, polished drawer, interaction feedback, visible hover/focus states, keyboard accessibility, responsive layout at 1440px, 1024px and 768px, no page overflow and no console errors. No exact screenshot or component layout is prescribed. Keep accessible names above so automated interaction remains possible; expose an activity container named Activity with ordered timestamp elements (time datetime=ISO), and summary values as labelled outputs. A semantic list is recommended but not required. Count outputs use accessible names Count Backlog, Count In Progress, Count Done, Count Critical/High/Medium/Low and Count <assignee>, including Count Unassigned. Analytics may be always visible or disclosed through an accessible control containing analytics, workload or breakdown in its name. Empty/error message wording and focusable control order are unrestricted. Drag evaluation uses physical pointer gestures and does not require native HTML drag events or any drag library.
